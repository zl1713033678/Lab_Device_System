# ADR-0001：采用 mDNS 局域网寻址与 device_code 资产解耦

- **状态**：已采纳（Accepted）
- **日期**：2026-08-25
- **关联代码**：[`main.py`](../../main.py)、[`esp32/main/main.ino`](../../esp32/main/main.ino)

## 1. 背景与问题（Context）
实验室局域网通过路由器 DHCP 分配服务端电脑 IP。如果 ESP32 固件将服务端 IP 硬编码为唯一目标，当电脑更换网卡、重启或 DHCP 租期变更时，所有已烧录节点均会失联；同时设备逻辑归属若绑定物理 IP，硬件换网或重启后资产坐标与履历会断裂。

## 2. 核心决策（Decision）
1. **逻辑锚点与网络解耦**：数据库以设备唯一物理码 `device_code`（如 `DEV-ESP32-001`）作为唯一索引锚点，设备房间归属、坐标与使用履历不依赖设备或服务端当前 IP。
2. **ZeroConf / mDNS 服务广播**：后端 `lifespan` 启动时通过 `zeroconf` 注册 `_http._tcp.local.` 服务，主机名为 `smartlab.local:8000`（按内网段优先排序枚举本机非回环 IP）。
3. **固件动态探测 + 静态 IP 降级**：ESP32 优先通过 `MDNS.queryHost("smartlab", 1500)` 解析服务端 IP；上报失败时重新触发 mDNS 探测；若局域网禁用组播，则回退至配置的备用静态 IP。

## 3. 后果与权衡（Consequences）
- **收益**：同一套固件无需因电脑 DHCP 变更反复重烧，设备跨房间/跨子网重启仍保留原有空间绑定与履历。
- **代价与约束**：依赖局域网允许 mDNS（UDP 5353 组播）；Windows 防火墙或隔离型校园网需放行或依赖降级配置；后续需将固件内硬编码备用 IP 外置为配网/构建参数（见 `BUG-001`）。
