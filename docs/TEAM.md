# 项目工作组

## 角色与分工

| 角色 | 主要责任 | 负责范围 | 默认进度笔记 |
|---|---|---|---|
| 项目负责人 / 架构师 | 需求拆解、优先级、架构边界、跨模块协调和最终验收 | 全仓库与对外契约 | project-lead.md |
| 后端与数据负责人 | FastAPI、领域逻辑、SQLite/迁移、报表、WebSocket 与 API 契约 | main.py、后端测试 | backend-data.md |
| IoT 与嵌入式负责人 | ESP32 固件、采样、设备协议、mDNS、断线重连与硬件验收 | esp32/、遥测契约 | iot-embedded.md |
| 前端与数字孪生负责人 | UI 交互、SVG 底图、状态同步、可访问性、前端可维护性 | static/ | frontend-ux.md |
| QA 与可靠性负责人 | 测试策略、回归、故障注入、验收门禁和缺陷分级 | tests/、模拟器、验收记录 | qa-reliability.md |
| 安全与发布负责人 | 密钥管理、认证授权、依赖治理、CI/CD、打包与发布 | 配置、构建脚本、发布产物 | security-release.md |

## 决策责任

- 模块内实现方案由模块负责人提案，项目负责人根据现有架构和验收目标确认。
- API、数据库、遥测报文和 WebSocket 消息是跨模块契约，变更需要后端、IoT、前端和 QA 共同评审。
- 安全门禁和测试门禁未通过时，不得标记发布就绪。
- 用户需求和已验证的实现优先于历史总结文档。

## 协作节奏

1. 项目负责人建立任务 ID、验收标准和依赖。
2. 模块负责人领取任务，在进度笔记登记开始状态。
3. 每个可验证增量完成后立即记录证据，不等到任务末尾补写。
4. 跨模块契约变更先交接，再由消费方拉取。
5. QA 完成独立复核后，项目负责人关闭任务并更新总记录。
