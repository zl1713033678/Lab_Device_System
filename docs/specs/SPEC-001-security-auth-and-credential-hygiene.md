## 1. 业务痛点与核心场景拆解
1. 固件 `esp32/main/main.ino` 含明文 Wi-Fi 凭据与内网 IP，且 `lab_devices.db` 曾被提交到 Git。
2. 当前任何局域网主机均可匿名调用删除设备/房间、改状态、伪造遥测或连接 `/ws/devices`。
3. 缺少自动化回归与安全检查门禁，修改 `main.py` 状态机或 `static/index.html` 缺乏防回归护栏。

## 2. 架构与算法设计（含遵循 AGENTS.md 红线的边界约束）
- **凭据外部化**：将固件网络参数迁移至未跟踪本地头文件（提供 `config.example.h` 模板），由环境所有者轮换已暴露密码；移除仓库对 `lab_devices.db` 的跟踪（保留迁移后初始化逻辑）。
- **管理鉴权与设备身份**：
  - 管理写/删/控制接口与 WebSocket 订阅引入会话或 Bearer Token 校验；
  - `/api/v1/telemetry/ingest` 接入设备级密钥或 HMAC 签名 + 时间戳/Nonce 防重放窗口，明确 HTTPS/WSS 反向代理终止方案。
- **输入与输出加固**：增加字段长度、数值范围与请求体限流；CSV 导出对 `=`, `+`, `-`, `@` 前缀做防公式注入转义；前端全面消除不可信字段的未转义 `innerHTML` 拼接。

## 3. 数据模型与接口扩展规划
- 配置外置：支持通过环境变量注入 `DATABASE_URL`、管理员凭据与设备密钥配置，服务测试层可在临时 SQLite 上独立运行。
- 固件模板：`esp32/main/secrets.example.h`（入库）与 `esp32/main/secrets.h`（`.gitignore` 忽略）。
